# นโยบายรับสิทธิ์โดยไม่ยืนยันอีเมล — 24 พฤศจิกายน 2569

เปลี่ยนตามคำขอผู้ดูแล: บัญชีที่เข้าสู่ระบบสำเร็จ มีอีเมลตรงกับรายชื่อที่ Admin เพิ่มไว้ และยังใช้งานได้ รับสิทธิ์ตามบทบาทที่ Admin กำหนดโดยไม่ต้องกดลิงก์ยืนยันอีเมล นโยบายนี้ใช้กับทุกบทบาทรวม Admin อีเมลใช้จับคู่รายชื่อ ไม่ใช่หลักฐานความเป็นเจ้าของกล่องจดหมาย

## ใช้กับระบบเดิม

1. ใน Supabase SQL Editor รัน **upgrade-email-access.sql ทั้งไฟล์** ใช้ได้กับฐานที่ติดตั้ง 006 แล้ว ไม่จำเป็นต้องรัน 007 ก่อน และรันซ้ำได้ ห้ามรัน install.sql ทับฐานเดิม ไฟล์ไม่ต้องแก้อีเมลหรือ UUID และไม่แก้ Auth users, รหัสผ่าน, email_confirmed_at หรือ email_verified
2. ใน Supabase Authentication → Sign In / Providers (หรือการตั้งค่าการสมัครผู้ใช้ของ project) ปิด **Confirm email** เปิด Email signup ตามเดิม และคง Anonymous Sign-ins ปิดไว้ การตั้งค่านี้เป็นของบริการ Supabase จึงไม่เปลี่ยนตามไฟล์ SQL ดู [เอกสารการตั้งค่า Auth](https://supabase.com/docs/guides/auth/general-configuration)
3. ปล่อยโค้ดเว็บรุ่นนี้ แล้วให้ผู้ใช้เข้าสู่ระบบใหม่ บัญชี nonglak.m@ubu.ac.th ที่เข้าระบบ Auth ได้อยู่แล้วจะรับสิทธิ์จากรายการ pending ในการโหลด workspace ครั้งถัดไป หากบุคลากรที่ยังไม่ได้สมัคร ให้สมัครด้วยอีเมลที่ Admin เตรียมไว้ เมื่อตั้งค่า Confirm email ปิด สมัครแล้วจะเข้าสู่พื้นที่ทำงานต่อได้

การส่งอีเมลกู้รหัสผ่านเป็นคนละขั้นตอนและยังใช้งานตามเดิม บัญชีที่ไม่มีรายชื่อจาก Admin ยังขึ้นรอสิทธิ์ ไม่มีการให้บทบาทตามข้อมูลที่กรอกเองตอนสมัคร

## เงื่อนไขที่ยังตรวจ

- ต้องมีเซสชัน Supabase Auth ที่ตรวจสอบได้; บัญชี anonymous, banned, deleted หรืออีเมลว่างรับสิทธิ์ไม่ได้
- ใช้อีเมลปัจจุบันจาก auth.users เท่านั้น ไม่ใช้ user metadata หรืออีเมลใหม่ที่ยังอยู่ระหว่างเปลี่ยน
- อีเมลซ้ำหลายบัญชีไม่รับสิทธิ์อัตโนมัติ องค์กรและหน่วยงานต้องเปิดใช้งาน
- ไม่คืนสิทธิ์ให้ profile/identity ที่ถูกปิด หรือสมาชิกที่ระงับ/เพิกถอน/หมดอายุ
- คงบทบาทและขอบเขตองค์กรของรายการที่ Admin เพิ่มไว้ รับสิทธิ์ซ้ำไม่สร้างสมาชิกหรือ audit ซ้ำ

Migration 008 เปลี่ยนเฉพาะ claim_workspace_invitations ไม่แก้ RLS หรือกฎการอนุมัติงาน ฟังก์ชันคืน emailVerificationRequired=false และ claimPolicy=admin_email_match โดยไม่อ้างว่าอีเมลถูกยืนยันแล้ว

หาก deploy โค้ดก่อนรัน SQL แล้วฐานเดิมตอบว่าต้องยืนยันอีเมล API จะแสดงว่าต้องอัปเกรดระบบ แทนการส่งผู้ใช้กลับไปยืนยันอีเมล การเชื่อมต่อ Auth และการรับสิทธิ์บุคลากรยังเป็นคนละชั้น
